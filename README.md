# IHMS-OHE — سامانه مدیریت معاینات طب کار

سامانه جامع مدیریت پذیرش، معاینات پزشکی حرفه‌ای، گردش کار تأیید متخصصان و صدور گزارش نهایی طب کار — با رابط کاربری فارسی (RTL).

## ✨ امکانات

- پذیرش مراجعه‌کننده (پیمانکاری / کارفرما / فرد مستقل)
- پرونده الکترونیک معاینات در ۹ بخش: مشخصات فردی، سابقه شغلی، عوامل زیان‌آور محیط کار، بیماری‌زمانی و شغلی، معاینه بالینی، آزمایش‌ها، ادیومتری/اپتومتری/اسپیرومتری/پاراکلینیک، ارجاع‌ها و نظریه نهایی
- گردش کار شش‌مرحله‌ای با نقش‌های مجزا (بهداشت حرفه‌ای، پزشک، ادیولوژیست، اپتومتریست، آزمایشگاه و…)
- نظریه نهایی چهارگانه: بلامانع / مشروط / عدم صلاحیت / پرونده ناتمام
- چاپ گزارش نهایی PDF (نسخه نهایی و پیش‌نویس «ناتمام»)
- گزارش‌های مدیریتی با نمودار و خروجی PowerPoint
- کنترل دسترسی نقش‌محور و تفکیک داده شرکت‌ها/پیمانکاران
- نمودار ادیومتری تعاملی، تقویم جلالی، تاریخ شمسی

## 🛠 تکنولوژی‌ها

Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · shadcn/ui · Prisma + Supabase (PostgreSQL) · Recharts · pptxgenjs

## 🚀 راه‌اندازی محلی (ویندوز / مک / لینوکس)

### پیش‌نیازها

- [Node.js نسخه ۲۰ یا بالاتر](https://nodejs.org) (در نصب، npm هم همراهش نصب می‌شود)

### مراحل نصب

```bash
# ۱) نصب وابستگی‌ها
npm install

# ۲) ساخت کلاینت Prisma (الزامی — مخصوصاً اگر npm اسکریپت‌های نصب را مسدود کرده باشد)
npx prisma generate

# ۳) اجرای سرور توسعه
npm run dev
```

سپس مرورگر را باز کنید: **http://localhost:3000**

> 🔐 اطلاعات ورود (نام کاربری و رمز عبور کاربران) به‌صورت محرمانه نزد مدیر سامانه است و در این مخزن عمومی منتشر نمی‌شود.

### دیتابیس: Supabase (PostgreSQL)

1. در [Supabase](https://supabase.com) یک پروژه بسازید.
2. فایل `.env.example` را به `.env` کپی کنید و `DATABASE_URL` و `DIRECT_URL` را از *Project Settings → Database → Connection string* پر کنید. `AUTH_SECRET` هم الزامی است (`openssl rand -hex 32`).
3. جدول‌ها را بسازید، یکی از دو راه:
   - فایل `supabase/migrations/20261019000000_init.sql` را در *SQL Editor* اجرا کنید (همراه با فعال‌سازی RLS)، یا
   - `npm run db:push`
4. کاربران اولیه: `npm run db:seed` (رمزها تصادفی‌اند و در `db/demo-credentials.json` ذخیره می‌شوند، نه در گیت).
5. اجرا: `npm run dev`

برنامه فقط از سمت سرور به دیتابیس وصل می‌شود؛ RLS روی همه جدول‌ها فعال و بدون policy است تا API عمومی Supabase (کلید anon) به داده‌ها دسترسی نداشته باشد.

### اجرای سریع روی GitHub Codespaces

در صفحه مخزن: **Code → Codespaces → Create codespace on main**. دیتابیس Postgres، ساخت جدول‌ها و seed خودکار انجام می‌شود و صفحه ورود روی پورت 3000 باز می‌شود. نام‌کاربری‌ها و رمزها در `db/demo-credentials.json` است. (این حالت فقط برای آزمایش است و برای استفاده واقعی از Supabase استفاده کنید.)

### استقرار (Vercel)

مخزن را در Vercel وارد کنید و متغیرهای `DATABASE_URL`، `DIRECT_URL` و `AUTH_SECRET` را تنظیم کنید. سپس یک زیردامنه (مثلاً `ohe.ihmsapp.ir`) به آن وصل کنید.

## 📁 ساختار پروژه

```
├── prisma/                 # اسکیمای دیتابیس + seed
├── supabase/migrations/    # اسکریپت SQL ساخت جدول‌ها
├── public/fonts/           # فونت وزیرمتن (self-host)
├── scripts/                # ناظر اجرای سرور توسعه (چندسکویی)
└── src/
    ├── app/api/            # APIها (auth, cases, companies, contractors, reports, ...)
    ├── components/
    │   ├── views/          # صفحات اصلی (داشبورد، پذیرش، پرونده‌ها، گزارش‌ها، ...)
    │   ├── sections/       # فرم‌های ۹ بخش پرونده
    │   ├── print/          # نمای چاپ گزارش نهایی
    │   └── ui/             # کامپوننت‌های shadcn/ui
    └── lib/                # احراز هویت، دیتابیس، توابع کمکی، تاریخ جلالی
```

## 🖨 چاپ گزارش

گزارش نهایی از مسیر پرونده → «چاپ گزارش نهایی» قابل چاپ/ذخیره PDF است. در صورت ناتمام بودن پرونده، نسخه پیش‌نویس با برچسب «پرونده ناتمام» صادر می‌شود.
